# 05 — Page Structure & Art Direction

Section-by-section intent for each page. Every section answers three questions: **why does it
exist · what is its visual idea · what makes it different from the section before it.** This
doc is filled in as each page cluster is built (Tasks 4, 6–10).

## Interior pages — shared opener

Every non-home page opens with **PageHeader**: a type-led opener on sand (label · display title ·
standfirst · gold rule), deliberately *not* a hero. This keeps interior pages calm and editorial,
and gives the whole site one consistent entry rhythm while the homepage stays the singular
full-bleed moment.

## Learn cluster

- **Learn hub** — four children at deliberately unequal scales, each with its own treatment
  (Initiatives = large editorial inset; Bulletin = a textual index, no image; Library = a framed
  archival plate; Reading Circle = the smallest, a botanical pair). A dark badge explainer teaches
  the four §10 labels; a Teacher's Desk block acknowledges it honestly as forthcoming. *Why: the
  default here is four equal cards, which would flatten a Yoga Mandala programme and an external
  book listing into the same object — exactly the blurring §23 forbids.*
- **Library (real)** — "reading room" opener, a subject "spine" (typographic index with counts),
  and an editorial record column where ~1 in 3 records carries a plate at varied placement.
  Detail pages are catalogue records with real rights/source and a link-out. *Why: 11 subjects and
  mixed-availability plates read as a catalogue, never a bookshop.*
- **Initiatives / Bulletin / Reading Circle** — list-led, badge-carrying, sample-marked.

## Connect cluster

- **Connect hub** — a doorway, not a landing page: embedded filter chips link straight to a
  pre-filtered directory (one click), and the non-endorsement caveat sits at equal weight in a
  dark section, never as fine print.
- **Directory** — live client-side filtering across seven §7.1 facets; results are editorial
  fragments at unequal sizes, never a face grid. Placeholder portraits are treated so they can't be
  mistaken for real members.
- **Profile** — treated portrait, a facts colophon, the Verified caveat spelled out, and an
  enquiry form (UI-only) — never public contact details (§16).
- **Experts** — a filtered view of the directory led by the §7.2 non-endorsement pull quote.

## Collaborate · Events · Discover

- **Sangha Board** — category chips filter a ruled post list; every post carries the Community
  Listing badge and a review date; contact routes through the portal.
- **Events** — a date-led index (the day numeral carries each row) with type filters; detail pages
  are date-led with link-out registration; partner events stay visibly distinct.
- **Discover** — one aggregated feed of the bulletin + community listings, each item keeping its
  own badge so origin is never blurred; a shared detail route resolves either kind.

## About cluster + Principles + Teacher's Desk

- **About** — opens with the mission as wall text (no image); pillars as column strips; the
  WhatsApp-vs-portal comparison as a real table; the IS / IS-NOT pivot as the boldest composition;
  the closing principle over a dark duotone. Founding story, who-runs-it and the Pranava wording
  are honest `[content pending]` blocks.
- **Principles / Guidelines** — a charter, not fine print: eight numbered principles, the §11
  claims distinction (with the single site-wide **arch mask**, T7), and the eight-state submission
  lifecycle published in full.
- **Governance** — §15's ownership principles as a numbered list; continuity administrators pending.
- **Teacher's Desk** — an honest forthcoming concept page: what it will hold, and why it waits. No
  countdown, no email capture.

## Join · Submit · Policy

- **Join** — an invitation (left: what membership means; right: a UI-only form). Nothing is sent.
- **Submit** — one engine, four typed forms, with validation and a clearly non-functional
  "validated — not sent" state, plus the §13 accuracy + consent declarations.
- **Privacy / Terms / Contact** — routed shells with `PendingBlock`, stating the content is being
  finalised and (for privacy) that no data is collected until it is published.
